# 显卡、系统与设备兼容性

macOS、Linux 的架构、依赖与设备限制见 [CROSS-PLATFORM.md](CROSS-PLATFORM.md)。以下为 Windows 后端的硬件兼容记录；Unix PDF 由 Poppler 处理，不使用 WinRT。

本项目不依赖特定显卡品牌，不链接 AMD SDK、CUDA、NVAPI 或 Intel 专用运行库。CPU 厂商和 GPU 厂商没有绑定关系；Intel/AMD CPU 配核显、AMD 独显或 NVIDIA 独显使用同一份 x64 EXE。

图片解码、缩放、灰度和扫描 PDF 编码由 Rust `image`/CPU 完成。PDF 页数和渲染由 Windows `Windows.Data.Pdf` 完成，底层是否使用 GPU 由系统组件决定。GDI 将页面位图提交打印机驱动；WIA 负责扫描。客户端仅显示 HTML 与 JPEG 预览，不使用 WebGL 或 GPU 计算。

## 支持目标与证据

| 环境 | 设计支持 | 当前验证范围 |
| --- | --- | --- |
| AMD 独显 | 使用统一 Windows 接口 | 本机 RX 580 2048SP，驱动 31.0.14051.5006：原生 PDF 和网页流程实测，详见验证记录 |
| Intel 核显 / Intel 独显 | 同一 EXE，无厂商分支 | 尚无对应硬件实测，需要运行兼容脚本与实际设备验收 |
| AMD 核显 | 同一 EXE，无厂商分支 | 尚无对应硬件实测 |
| NVIDIA GTX/RTX 等 | 同一 EXE，不需 CUDA | 尚无对应硬件实测 |
| 混合显卡 / 远程桌面 | 依赖系统 PDF 组件及当前会话 | 尚未实测，切换显卡/会话后需重验 |
| 无独显 / 基本显示适配器 / 虚拟机 | 不要求独显，系统组件须正常 | 没有保证所有基础驱动环境可渲染 PDF，需现场检测 |

“无厂商绑定”不等于“所有驱动版本都已测试”。当前没有可强制 Windows PDF 使用 CPU 的产品开关，也没有第二套软件 PDF 渲染后端；不能把浏览器关闭硬件加速当作服务端 PDF 故障的修复。若某机器系统 PDF 持续失败，可先用 PNG/JPG 打印，或更新驱动/系统；将来引入软件 PDF 库需评估包体、许可证和安全更新，再同时接入检查、预览及打印路径。

## 验收矩阵

在各类主机分别运行 `scripts/check-compatibility.ps1`，记录报告、EXE 哈希、系统版本和驱动版本；检查输出预览是否完整清晰。随后执行：

1. 打开网页，上传普通 PDF、多页 PDF、透明 PNG 和 JPEG；检查翻页、方向、文字与白底。
2. 用真实打印机验证一页黑白、一页彩色、页码选择、两份、单双面和横向；纸张不支持时应禁止提交。
3. 用真实 WIA 扫描仪验证平板/支持时单页 ADF，100/200/300 DPI、灰度和彩色、三种输出格式。
4. 重新登录确认自启动静默运行，关闭开关后再次登录确认不自启；查看 Windows 启动应用未被外部禁用。
5. 启用本次防睡眠确认空闲时共享可用；退出后确认恢复系统电源行为。
6. 在测试数据目录执行重启/超时场景，确认任务不自动重复打印；真实任务超时后须人工核对打印机。

同事的浏览器可以在 Windows/macOS/Linux/手机上运行。当前发行目标为 Windows x64 主机；Windows ARM64、32 位 Windows、Server Core 和旧版 Windows 不属于已验收发行目标。扫描限 WIA 单页，打印需要 Windows 可用的打印驱动，GPU 兼容不能代替设备兼容验收。
